# QECO × Fogify: 단계별 진행

연구 주제는 「네트워크 및 엣지 서버 자원 상태를 고려한 학습 기반 동적 작업 오프로딩」이다.
작업마다 실행 위치를 로컬 / 엣지 서버 1 / 엣지 서버 2 중에서 고르고, 작업 완료 시간(TCT)으로 평가한다.

| RQ | 질문 |
|---|---|
| RQ1 | 로컬과 엣지 서버가 뒤바뀌는 지점(break-even)은 RTT, 대역폭, CPU 부하에 따라 어디인가 |
| RQ2 | 엣지 서버가 여러 대이고 서로 상태가 다르면 선택이 어떻게 달라지는가 |
| RQ3 | 학습 기반 정책이 고정 규칙·휴리스틱 정책보다 나은가 |

## 단계별 요약

진행 순서는 1 → 2 → 3 → 4 → 4.5 → 3.5 → 5 → 6이다. Phase 4에서 학습과 평가의 조건이 서로 다르다는 것을 발견해서 4.5와 3.5를 끼워 넣었다.

|---|---|---|---|---|

| 2 | 원본 QECO(학습 기반 오프로딩) 코드를 그대로 돌려 재현 | 준비 (RQ3 비교 대상) | 완료 | [phase2-upstream.md](phase2-upstream.md) |

## 용어

- **로컬:** 작업이 생긴 기기.
- **엣지 서버:** 로컬과 클라우드 사이의 서버. 코드 이름은 `local`, `edge-server-1`, `edge-server-2`이다.
- **사후 최적 (Offline-Opt):** 각 작업을 세 위치에서 모두 실측한 뒤 가장 짧은 TCT를 고른 이상적 기준이다. 정책 성능은 이것 대비 손해(regret, ms)로 나타낸다.
- **closed-loop:** 앞 작업이 끝나고 쉬는 간격(평균 200 ms)이 지난 뒤 다음 작업이 생긴다. 실시간 앱의 프레임 처리 방식과 같다.

코드와 결과는 `examples/qeco-fogify/`에 있다.
